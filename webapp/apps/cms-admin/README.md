# hush CMS admin

The editor for the hush blog at cms.behu.sh: posts by status, a Markdown editor
with the live preview behu.sh will show, post settings, images, history and
publishing. It is the `@hush/cms-admin` app in the [web workspace](../../README.md);
the CMS (`apps/cms`) serves the built admin on its own origin and is its API.

Built with React 19, Vite, TanStack Router (file-based routes in `src/routes`)
and TanStack Query, the components and tokens of Shade, Ghost Admin's design
system (`src/components/ui` and `@hush/theme`, MIT), on Radix, CodeMirror 6, and an API client generated by Orval
from the CMS's OpenAPI document.

## Develop

Needs a PostgreSQL server for a throwaway database, the same one the CMS tests use:

```sh
cd webapp
bun install --frozen-lockfile
cd apps/cms-admin
HUSH_TEST_DATABASE_URL=postgresql://hush:hush-test@127.0.0.1:5432/hush_test bun run dev
```

Open http://localhost:5174/__e2e/sign-in in Chrome or Firefox. `bun run dev`
starts Vite with hot reload and a local CMS (`apps/cms`, `admin:server`) with two
sample posts and a sign-in that needs no GitHub; Vite forwards `/v1`, `/auth`
and `/blog/media` to it. Safari keeps no secure cookie on plain-HTTP
`localhost`; use `bun run test:admin` in `apps/cms` to see the admin in WebKit.
The TanStack Router and Query devtools appear only in development.

## Checks

```sh
bun run lint          # route tree, then TypeScript
bun run api:check     # the generated client matches apps/cms/openapi/hush-cms.json
bun run build
cd ../cms && bun run test:admin   # browser journeys CMS-001 to CMS-008 (desktop, phone, WebKit)
```

After an API change in `apps/cms`, run `bun run api:openapi` there and
`bun run api:client` here, and commit both generated files.
