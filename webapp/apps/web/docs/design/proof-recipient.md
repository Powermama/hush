# A message with a visible history

## Brief and direction

The recipient arrives to inspect someone else's words. Show the real message first, make its signed history understandable at a glance, then invite the recipient to try hush. Reuse the full-width public header and the existing download destination. Never manufacture a waveform, an identity, missing events, or intermediate message text.

Palette: porcelain #FAFBFC, graphite #24272B, slate #626973, recording blue #356B89, AI plum #76589A, signature green #267452. Use the site's native system sans for interface and message, with tabular numerals for recorded times. Keep message lines under 65 characters.

Layout:

```
shared header                                        Download

Verified hush message                         signature seal
author disclosure
The actual signed words, large and readable
voice / local AI / manual changes, when recorded

The message's history                    Signed wording
connected, colour-coded event icons      original / changes
recording + time                         private comparison
cleanup + time
AI or typing + time
signed + time

hushy       Give your words a story, too.       Download for Mac

technical details / privacy
```

The memorable visual is the connected event trail, using meaningful microphone, keyboard, sparkle, cleanup, revision, and signature symbols. Avoid repeated dashboard cards, fake recording playback, busy backgrounds and an animation that delays reading. The message has one quiet paper surface; the history sits in the page rather than another set of equal cards. Native details controls keep deeper wording and cryptographic information available.

## Review against the brief

The signed message is the headline, not another marketing slogan. Event types and truthful language do more work than decoration. A typed-origin record never inherits microphone claims. Local AI is explicitly labelled even when a persona has a name. Version 1 events do not receive invented timestamps. Self-declared author names remain visibly self-declared. Verification proves the signed record, not the speaker's identity or the truth of the words.

All content is derived locally from the already verified manifest. No new API, tracking, external images, model, or WebGL scene. The download invitation uses the existing release component and a static shared SVG mascot. Failure and missing-key states remain distinct from successful verification. Responsive history remains in chronological DOM order and keyboard accessible; no automatic carousel or per-frame work.

## Verification

Use signed browser fixtures for voice plus AI, typed origin, mixed voice/typing revisions, and legacy proofs. Capture desktop and mobile views. Check exact and mismatching received text, valid download destinations, private fragment preservation, expired/revoked/missing-key/invalid states, and overflow with long messages. Run the required type, server, API contract, and browser checks.
